## 1. Executive summary (для нетехнического читателя)

GUTTERCAPS — это коллекционная gacha-игра на Solana: четыре смарт-контракта (ядро, рынок, стейкинг, арена), серверная половина и клиент. Аудит **не нашёл ни одной критической уязвимости, позволяющей напрямую украсть чужие средства или бесконечно печатать токен $CG** — mint-авторити токена принадлежит только контракту с жёстким расписанием эмиссии, а все денежные перемещения проходят через PDA-эскроу с корректными проверками владельцев. Найдена **одна серьёзная (High) уязвимость дизайна**: если игрок продаст на маркете ещё не «отчеканенный» ваучер из купленного компрессед-пака, пакет покупателя навсегда «кирпичится» — ни довести сделку до конца, ни вернуть остаток денег невозможно, деньги запираются в контракте навечно. Эта же механика позволяет получить «мёртвый вес» в стейкинге (phantom weight), разбавляя чужие награды. Экономическая модель при базовом сценарии (5 000 DAU) сжигает 52 % дневной эмиссии и устойчива к гиперинфляции: годовой прирост предложения ≈ 4 % от капа при полном отсутствии buyback; activity-guard корректно ограничивает эмиссию расписанием даже при вранье оракула, но сам заявленный «безоракульный» guard на самом деле питается off-chain кипером (документация врёт). Централизация существенная, но честно задокументированная: пять горячих ключей-киперов (crank, burn-oracle, два reward-оракула, battle-oracle) с ограниченным blast radius каждый; матчи PvP рассчитывает сервер, контракт лишь ограничивает дневные выплаты оракула. Код необычно дисциплинирован: ноль TODO/FIXME в программах, синхронизация констант Rust↔TS гейтится CI, 83+ сценария localnet-тестов, золотые векторы роллов; при этом production-деплой ещё не состоялся, program-id на mainnet — публичные плейсхолдеры, и собственный же launch-gate документ (`docs/09`) ставит проекту «к продукту готовы — к деплою нет». Вердикт аудита совпадает: **код достоин внешнего аудита и devnet-soak, но не mainnet в текущем виде** — прежде всего из-за находки High, одной невыписанной бомбы в program-id и дрейфа «backend-authoritative» части.

## 4. Кибер-раздел: threat model

**Активы:** SOL/USDC/SKR/$CG в vaults и эскроу; эмиссия $CG; фишки (Core + Bubblegum V2); SKR-призовой пул; целостность RNG; репутационная целостность рынка (floor/история).

**Границы доверия (все задокументированы внутри кода/README — это правильная практика):**
1. **Upgrade authority** — планируется Squads 3/5 + 48 ч timelock (описано в Anchor.toml/ops); состояние «плейсхолдер id + холодные пары» см. F-05.
2. **Admin (per-program)** — set_config/set_pack/set_oracles/set_arena/set_pauser/pause. Blast: конфиги, поставки SKU; деньги игроков напрямую не двигает (sweep_vault под инвариантом liab), исключение — `set_season_pool` в arena (F-06-сосед, treasury-уровень привилегия у admin-ключа).
3. **Hot pauser (SEC-H2 fix)** — мгновенный pause create/accept/buy-флоу; не может снять деньги.
4. **Crank** — permissionless settle (reveal→open/fuse/battle) + SEC-M7 rent reclaim. Не может подменить исход: roll детерминирован `expandRandomness(packSeed(value,qty,pack_no))` и перепроверяется программой; crash-crank = протокол уже permissionless, игрок может сам.
5. **burn-oracle** — F-02: влияет только на guard (30 %→100 % расписания), клэмп + кэпы on-chain.
6. **quest/season-oracles** — publish/revoke корней в пределах slice_budget + item/chip/root капы; заявленные суммы — реальная эмиссия, но ограниченная расписанием.
7. **battle-oracle** — F-06: выбор победителя, до daily-cap.
8. **Switchboard TEE** — commit(bind slot−1)→reveal(подпись оракула проверяется программой SB)→permissionless settle; peek-n-cancel закрыт SEC-C3/10 800 слотами/PDA-authority.
9. **Pyth** — receiver-пин `rec5EKMGg6MxZYaMdyBfgwp4d5rB9T1VQH5pJv5LtFJ`, feed-пин SOL&SKR, freshness ≤60 с, ±2 % conf; ключ pusher'а не является доверенным (только liveness).
10. **DAS-индексатор** — fail-closed чтение листов (proof+hash валидация on-chain у CPI Bubblegum; «DAS display JSON — не authority»).
11. **Backend API** — SIWS-куки+CSRF, rate-limit /24, anti-farm (Turnstile/device/flags), авторитетен по ranked-матчам/квестам/рефералам в пределах on-chain капов.

**Векторы:**
- *Front-running*: buy-гварды expected_price/currency (есть), accept_offer listed-флаг (есть), update_price без rate-limit — выкуп по старой цене в той же пачке блокируется expected_price; рынок офферов F-08/09; idx-фронтран роллов невозможен (commit до value, assert_fresh_commit).
- *RNG manipulation*: Switchboard TEE + commit-reveal + PDA-authority (SEC-C3 part 2); sb_mock только localnet-фича (F-19); арена VRF отдельным kind 2.
- *DoS*: пустой crank → 72-мин окно и refund; cap-exhaustion арены → 30-мин refund; Pyth-устаревание → отказ только SOL/SKR-веток (USDC/$CG живут); DAS-аутедж → post-mint рынок встаёт (fail-closed, F-15 совместимо). PDA-спам create_battle — F-20.
- *Oracle manipulation*: pusher/burn-oracle/battle-oracle — см. выше, каждый с клэмпом; $CG цена — F-13.
- *Client trust*: клиент — тонкий; цены через `/packs/quote` (per-int max_lamports), сборка ix в `client/src/chain/ix/*` зеркалит Rust (chain.test.ts + golden). Риск фишингового подлога quote — смягчён max_lamports на подписи.
- *Централизация*: 5 горячих ключей у студии + treasury SKR single-signer (`HPMr5r…`, docs признаёт: «on-curve, не Squads») — для призового пула *по обещанию*, не по контракту. Честно: 15/10/5 % — политика, публикуемая через `/rewards/skr-pool.funding` (dueMicro vs surplusMicro) — внечейн-обещание с чейн-верификацией поступлений; не нарушение, но знайте: withdraw_skr (мультисиг) может забрать незарезервированный budget.
