# Fix pass 2026-10-03 · `setup` на devnet: `ERR_MODULE_NOT_FOUND: Cannot find package '@/shared'`

Прогон `bash scripts/mac-devnet.sh` прошёл `deploy` (13530 с, `verify-deploy onchain OK` для devnet) и
умер на первом шаге следующего этапа — `npm run setup`:

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@/shared' imported from
  /Users/zlata/LeoGamesStudio/guttercaps/client/src/shared/lib/lore.ts
```

## 1. Причина: bare Node не умеет алиасы

`scripts/setup.ts` брал лор из клиентского ре-экспорта — `../client/src/shared/lib/lore.ts`. Этот файл
импортирует `@/shared/i18n`, то есть алиас из `client/tsconfig.json` (`paths: { "@/*": ["src/*"] }`).
Алиас знают Vite (`client/vite.config.ts`), vitest (`tests/localnet/vitest.config.mts`) и `tsc`; `node`
не знает его по определению — `npm run setup` исполняется как
`node --experimental-strip-types scripts/setup.ts`, а этот резолвер ищет `node_modules/@/shared` и падает.

Канонический источник данных — `packages/economy/src/lore.ts` (клиентский файл лишь ре-экспортирует его),
поэтому правка — импорт напрямую из пакета, ровно так же, как это делает `scripts/art-pipeline.ts`.

## 2. Почему это не поймал ни один гейт

Класс «работает у tsc и vitest, не работает у node» проходил между проверками:

| Проверка | Почему молчала |
|---|---|
| `npm run verify` | не загружает ни одного скрипта, который исполняется bare Node; `security:static` смотрит исходники, а не граф импортов |
| `tsc` (root `tsconfig.json`, `include: ["scripts/**/*.ts"]`) | его `paths` тоже мапят `@/*` на `client/src/*`, поэтому компилятор считал импорт корректным |
| ночной джоб `e2e-devnet` (единственный, кто запускает `setup`) | строка `DRY_RUN=1 … npm run setup \|\| echo '::warning::setup dry-run failed (expected until G-0 keys exist)'` — глотает и «нет ключей», и «модуль не загрузился» |
| локальная разработка | `vitest` и `vite` алиас резолвят, поэтому импорт выглядел рабочим |

## 3. Правка

| Файл | Что внутри |
|---|---|
| `scripts/setup.ts` | `COLLECTIONS` берётся из `../packages/economy/src/lore.ts`; комментарий у импорта называет ловушку (скрипты под bare Node не импортируют `client/src`) |
| `client/src/shared/lib/lore.ts` | шапка: файл для UI и localnet-спеков, «NOT for the node scripts» + имя ошибки, которую это стоило |
| `packages/economy/src/lore.ts` | в списке потребителей сказано, что `scripts/setup.ts` читает этот файл напрямую |

## 4. Гейт: `tests/security/node-entrypoints.test.ts` (в `npm run security:static`)

Правило: **всё, что `package.json` / `ci.yml` просят исполнить через bare `node`, обязано резолвиться и
загружаться самим Node.**

- **точки входа** читаются из всех манифестов воркспейса (root + `workspaces`) и из строк `node …` в
  `.github/workflows/*.yml` — не из ручного списка;
- **резолвит сам Node** — дочерним процессом с `--experimental-import-meta-resolve`: без этого флага
  `import.meta.resolve(spec, parent)` **игнорирует parent** (измерено на v22.22.3) и резолвит относительно
  вызывающего файла, то есть наивная версия «проверяет» всё против каталога теста и всегда зелёная;
- **обходится весь статический граф** (не первый хоп), у каждого падения печатается цепочка
  `jobs → файл → файл` и имя скрипта из манифеста;
- **правила**: расширение, которое Node умеет грузить (не `.tsx`); только erasable-синтаксис (enum,
  namespace, `import x = require(…)`, parameter property — `--experimental-strip-types` их отвергает, а
  `declare`/`import type` стирает, поэтому они разрешены); файл не из `client/src` (дерево Vite);
- **граница названа, а не подразумевается**: точки входа под транспилирующим загрузчиком
  (`node --import tsx …` — все скрипты backend) перечисляются как пропущенные: tsx транспилирует то, что
  стриппер отвергает, и у того же графа там другие правила;
- **три теста**: правило на реальном дереве; «гейт не вакуумный» (состав точек входа, что резолюция
  действительно шла по импортам, счётчик динамических спецификаторов); мутационные фикстуры во временном
  дереве — алиас, `.tsx`, enum, parameter property, отсутствующий файл, импорт из `client/`, и три
  контроля, которые молчать обязаны (спецификатор в комментарии/строке, `import type`, `declare`).

Гейт проверен на исходной ошибке: с возвращённым `'../client/src/shared/lib/lore.ts'` он валится ровно
на неё и печатает `package.json#setup → scripts/setup.ts → '../client/src/shared/lib/lore.ts' — the client
tree is Vite's (aliases, CSS, JSX) — move what is shared into packages/ so Node can load it`.

## 5. Прогон

- до правки: `DRY_RUN=1 node --experimental-strip-types scripts/setup.ts` — **та же ошибка** дословно
  (`Cannot find package '@/shared' imported from …/client/src/shared/lib/lore.ts`); curl на
  `api.devnet.solana.com` из песочницы — exit 35, то есть сеть до devnet здесь закрыта и прогон
  проверялся до первого RPC-вызова;
- после правки: `DRY_RUN=1 ANCHOR_WALLET=… node --experimental-strip-types scripts/setup.ts` — грузится,
  печатает `cluster/wallet/treasury/buyback/config` и `▶ mints`, дальше упирается в `fetch failed`
  (нет egress до devnet — ограничение песочницы, не кода);
- `npm run security:static` — 183/183 (включая 3 новых теста);
- `npm run verify` — **exit 0** целиком (lock-integrity, economy, client typecheck/test/build, bundle:check
  329.2 ≤ 350 KB, backend typecheck/test, landing, api:check, env/schema, selftest'ы cargolock/junit/cu/macdevnet
  (153 проверки), state:layout 29 аккаунтов, fonts, docs:refs 278 ссылок);
- `npm run setup` — та же строка, что исполняет mac-devnet на этапе `setup`: печатает
  `cluster/wallet/treasury/buyback/config` и `(DRY_RUN — nothing is sent)`, дальше `▶ mints`.

## Что делать на Mac

Обновить ветку и продолжить с этапа, на котором остановились (этап идемпотентен):

```bash
bash scripts/mac-devnet.sh --from setup
```
