# Фазированный ончейн-план: Г (ноль своих программ) → В (тонкая программа)

Конкретика к `docs/DAPP-STORE-LAUNCH.md`. Ставка ренты — измеренная у кластера
5 080.65024 лампорта/байт (`reports/BUDGET-SBF-2026-10-01.md`); перед деплоем
переспросить `solana rent <bytes>`, ставка не зашивается. Формула:
`rent = (длина данных + 128) × ставка`. Все цифры — освобождение от ренты
(rent-exempt), т.е. возвратный залог, а не сгоревшая плата.

---

## 1. Схема авторитетов (обе фазы)

| Ключ / авторитет | Кто держит | Что может | Чего НЕ может |
|---|---|---|---|
| Treasury (казна) | Squads-мультисиг (`SQUADS_TREASURY` уже в setup) | принимать оплату, выплачивать награды | минтить фишки |
| Tree authority (минт cNFT) | отдельный кейпейр бэкенда (KMS/энклав), дневные лимиты в коде | минтить в деревья районов | трогать казну |
| BATTLE_ORACLE | бэкенд (`BATTLE_ORACLE_KEYPAIR`, уже есть) | подписывать итоги матчей | минтить, платить |
| BURN_ORACLE | бэкенд (`BURN_ORACLE_KEYPAIR`, уже есть) | репортить сжигания в эмиссию | всё остальное |
| QUEST/SEASON/SET_ORACLE | бэкенд (уже заведены в setup) | засчитывать квесты/сезоны/сеты | минтить активы |
| MINT_ORACLE (новое, фаза В) | бэкенд, отдельный от tree authority | подписывать разрешения на минт | сам минтить не может — минтит программа по его подписи |
| Upgrade authority программ (фаза В) | Squads-мультисиг | обновлять тонкую программу | — |

Принцип: компрометация одного ключа не даёт чужой домен. Ключ минта не лежит
на сервере в открытом виде (KMS-подпись), публичный журнал минтов — на Verify.

## 2. Фаза Г — ноль своих программ (запуск в стор)

Используются только чужие задеплоенные программы: SPL Token, Metaplex
Bubblegum (минт/бёрн/трансфер cNFT), MPL Core (коллекции районов).

### Транзакции игрока

| # | Действие | Кто подписывает | Что происходит | Комиссия сети | Рента |
|---|---|---|---|---|---|
| 1 | Вход | кошелёк (SIWS-сообщение, не транзакция) | сессия бэкенда | 0 | 0 |
| 2 | Покупка пака | кошелёк | перевод SOL/USDC/SKR в казну + memo с ID заказа | ~0.000005 SOL, платит игрок | 0 |
| 3 | Открытие пака | бэкенд (tree authority) | бэкенд видит оплату в индексе → минтит cNFT игроку по заранее опубликованному SlotHashes-коммитменту; сид раскрывается в транзакции минта, Verify пересчитывает | платит бэкенд | 0 (cNFT без аккаунта) |
| 4 | Слияние | кошелёк + бэкенд | игрок подписывает бёрн 3 cNFT (Bubblegum) → бэкенд проверяет бёрн и рецепт → минтит результат; кулдаун результата (1ч/6ч/24ч/48ч/72ч по таблице) ведёт бэкенд и показывает в UI | бёрн — игрок, минт — бэкенд | 0 |
| 5 | Маркет | кошелёк | листинг/покупка на существующих площадках cNFT (их программы и эскроу) | игрок | 0 наших |
| 6 | Стейкинг (мягкий) | подпись-сообщение | фишка остаётся у игрока; бэкенд начисляет, пока индексатор видит владение; продал — начисления стоп | 0 | 0 |
| 7 | Награды квестов/пасса | бэкенд | перевод $CG с пула казны по клейму внутри бэкенда | платит бэкенд | 0 |

Честные ограничения фазы Г (писать в правила, не прятать): выпуск и кулдауны
исполняет сервер, а не контракт. Смягчение: коммитмент шансов до оплаты
(SlotHashes), публичный журнал минтов на Verify, потолок эмиссии = размер
деревьев (больше, чем влезает в деревья, выпустить физически нельзя).

### Смета фазы Г (разовый залог)

| Аккаунт | Размер | Рента, SOL |
|---|---|---|
| Деревья cNFT ×8 (depth 14, buffer 64, canopy 0) | 31 800 Б | 1.2977 |
| TreeConfig ×8 | ~152 Б | 0.0114 |
| Минт $CG | 82 Б | 0.0011 |
| MPL Core коллекции ×8 | ~250 Б | 0.0154 |
| Токен-аккаунты казны/пулов ×11 | 165 Б | 0.0164 |
| LUT (опционально) | ~1 700 Б | 0.0093 |
| **ИТОГО фаза Г** | | **≈ 1.35 SOL** |

Запас деревьев depth 14 — 131 тыс. фишек суммарно. Издательские NFT портала
(+~0.02 SOL) считаются отдельно. Программы: **0 SOL** (своих нет).
Чувствительность: при классической ставке 6 960 цифры ×1.37 (деревья 1.78 SOL).

## 3. Фаза В — тонкая программа-расчётчик (на выручку)

Одна программа вместо четырёх. Только то, что обязано быть бесспорным:

### Инструкции (полный список)

1. `init_config(oracle_pubkeys, treasury)` — конфиг + счётчик эмиссии (потолок).
2. `buy_pack(order_id, currency, amount)` — оплата в эскроу программы, запись заказа.
3. `settle_pack(order_id, ed25519_sig)` — проверка подписи MINT_ORACLE
   (Ed25519Program-интроспекция: кошелёк, ID заказа, нонс, срок) → минт cNFT
   через CPI в Bubblegum от PDA-авторитета дерева; счётчик эмиссии += n.
4. `claim_reward(merkle_proof)` — выплата $CG по Merkle-руту наград, который
   публикует бэкенд (рут — одна транзакция в сутки/неделю).
5. `anchor_root(root, kind)` — публикация рутов состояния (награды/лидерборд).
6. `escrow_list / escrow_buy / escrow_cancel` — маркет без третьей стороны:
   cNFT уходит в PDA-эскроу, покупка — атомарный обмен.
7. `set_oracles / set_limits` — мультисиг-админка: ключи ораклов, дневные лимиты.

Чего в программе НЕТ (это и даёт размер): рецептов слияния, шансов, пити,
арены, квестов, XP — всё считает бэкенд, программа проверяет только подпись
оракла домена, нонс и потолки. Fusion-кулдауны фаза В по-прежнему ведёт
бэкенд; ончейн-блокировку результата даёт перевод результата в эскроу-PDA
на срок кулдауна (опция, инструкция `settle_pack` с флагом lock).
