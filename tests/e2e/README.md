# E2E (Playwright) — два тира, и они значат разное

```bash
npm run e2e:install                 # chromium (+ системные зависимости на Linux; на macOS — только браузер)
npm run e2e:mock                    # build (VITE_API_MOCK=1) → typecheck спеков → Playwright
npm run e2e                         # то же, что было собрано ранее, все проекты (desktop + Pixel 7)
E2E=1 PWDEBUG=1 npx playwright test mock-shell --project=seeker-class   # отладка на «Seeker-классе»
```

## Тир 1 — `mock-shell.spec.ts` (PR-гейт)

Прогоняется в CI на каждый PR и **не требует ни сети, ни кошелька**: поднят `vite preview` на
прод-сборке с `VITE_API_MOCK=1`, то есть тестируется реальный бандл (entry-граф, modulepreload, роутер,
i18n), а не dev-сервер.

Что он покрывает из `docs/06` §1.2–1.3:

| проверка | зачем |
|---|---|
| шелл красится, **запросы не уходят за пределы origin** | `VITE_API_BASE`, запечённый на другой хост, — это «белый экран» в проде, и unit-тест его не видит |
| каждый публичный маршрут рисует заголовок и не оставляет `pageerror` | 10 экранов против одного роутера; падение роута — это пустая вкладка, а не красная сборка |
| кошелёк-гейт редиректит с `?next=`, а не рисует полстраницы | глубина ссылок (`/shop/opening/:nonce` из пуша/почты) должна выживать |
| 4 SKU, цена и шанс видны **до** подписи, и всё денежное — в clean-zone | §1.2 «Магазин»: честность до транзакции, а не в чеке |
| футер → `/legal/terms` и `/legal/privacy`, алиасы `/terms` `/privacy` резолвятся, баннер «не вычитано юристом» на экране | docs/09 §5.2; мёртвая ссылка в юридическом блоке — это отказ стора, а не косметика |
| смена языка меняет `<html lang>` и текст | 7 локалей — не опция, а требование PRD |
| axe (serious+critical) на `/shop` и `/market` | §1.3 WCAG AA на денежных экранах |

Стейкинг/фьюжн в этом тире **не** проверяются: они за `RequireWallet`, а расширения для кошелька тут нет — они
в тире 2 и в юнит-тестах. Порог — только `serious`/`critical`: первый прогон axe на игровом UI выдаёт
охапку `moderate`-придирок к декоративным слоям, а красная проверка, который нельзя починить за день, через
месяц просто отключают.

## Тир 2 — `devnet-loop.spec.ts` (T-E-00, «определение готовности»)

Три покупки одним кошельком: commit → reveal → open → `/verify`, с перезагрузкой на середине и финальной
проверкой, что `crank.abandoned == 0` (docs/06 §1.1). Файл **ни разу не выполнялся там, где был написан**
(нет браузера, нет funded-сида, нет расширения), и это не мелочь: порядок шагов и ассерты взяты из спеки,
а селекторы внутри попапа Phantom — самое хрупкое место, потому что расширение живёт по своему релиз-циклу.
Перед тем как ставить это гейтом, нужен один ручной прогон:

```bash
E2E_PHANTOM_EXTENSION=/путь/к/unpacked/phantom \
E2E_DEVNET_MNEMONIC="…" \
E2E_APP_URL=https://app.guttercaps.gg \
npx playwright test devnet-loop --headed --debug
```

Файл скипается, если первых двух переменных нет, — поэтому ночной прогон сейчас и `continue-on-error`
(`.github/workflows/ci.yml`, job `e2e-devnet`). Отдельно: ключ-логин «вставь seed-фразу» в клиенте
намеренно не реализован (это была бы дыра, а не фича), поэтому альтернативы расширению нет.

## Что нашли первые прогоны в CI

Не абстракция — результаты запуска `.github/workflows/ci.yml`, job `e2e`:

- **приложение ходило вовне**: `client/index.html` тянул Google Fonts (`fonts.googleapis.com` +
  `fonts.gstatic.com`). Под прод-CSP (`font-src 'self' data:`, `style-src 'self' 'unsafe-inline'`) эти
  файлы всё равно блокируются, то есть в проде шрифт не грузился никогда, а IP посетителя уходил на каждую
  загрузку страницы — вопреки нашему же тексту в `/legal/privacy`. Убрано, шрифты доведены до self-host
  (`client/public/fonts` + сгенерированный `client/src/shared/ui/fonts.css`, гейты `npm run fonts:check`
  и `client/src/shared/ui/fonts.test.ts`); рецепт и разбор — `client/public/fonts/README.md`.
  Это теперь сторожат с двух сторон: `npm run bundle:check` отвергает off-origin ссылки в собранном
  `index.html` **и в собранных CSS/JS**, а здесь, в браузере, — утверждение «ни один запрос не уходит за
  пределы origin».
- **тот же баг, в двух других местах** (второй прогон, уже после правки HTML): `@import url(…)` в
  `@solana/wallet-adapter-react-ui/styles.css` (DM Sans) и инъекция `<link>` (Inter Tight) из
  `@solana-mobile/wallet-standard-mobile` — она происходит в конструкторе EmbeddedModal, то есть на загрузке
  страницы, а не когда мобильный пользователь открыл этот модал. Проверка по одному только `index.html`
  этого не видела; теперь правило живёт в сборке (`noThirdPartyAssets` в `client/vite.config.ts`) и проверяется по
  dist CSS/JS. Ценность тира ровно в этом: браузер не знает, «какой файл» виноват, он знает, что запрос был.
- **`/shop`: `aria-required-children` (critical)** — `<div role="tablist">` с двумя обычными `<button>`
  внутри: семантика для скринридера без клавиатурной части. Починено на сторону семантики (роли,
  `aria-selected`, `aria-controls` только у выбранной вкладки, roving `tabIndex`, ←/→/Home/End), а не
  удалением роли; закреплено юнит-тестом без браузера (`client/src/app/smoke.test.tsx`).

## Локализация: сообщения и сохранённые наборы

```bash
npm run e2e:build
npx playwright test tests/e2e/live-localization.spec.ts --project=desktop-chromium --workers=1
npm run e2e:errors
```

`live-localization.spec.ts` — 7 языков, 360/1280 px: открытое уведомление о наградах, смена
формата чисел, старые и новые наборы слияния, перезагрузка, загрузка/удаление, подписи выбранной
рецептуры. Это обычная mock-сборка; тестовый Wallet Standard не разрешает подпись.

`e2e:errors` создаёт **отдельную** сборку в `.arena/error-client` с `VITE_API_MOCK=0`, потому
что mock-ветка обходит подпись входа. HTTP/RPC/WS перехватываются; тестовый кошелёк либо
отказывает в подписи сообщения, либо отдаёт фиктивные байты локальному перехваченному verifier.
Никаких приватных ключей, настоящего API или денежных транзакций. Эти 14 тестов специально
пропускаются в обычном mock-прогоне и запускаются отдельным шагом CI.

При недоступности CDN браузер можно указать через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`;
бинарник и необходимые библиотеки должны быть установлены отдельно и не добавляются в Git.

## Локализация: числа, даты и восстановление входа

```bash
npm run e2e:build
npm run e2e:types
npx playwright test tests/e2e/numeric-localization.spec.ts --project=desktop-chromium --workers=1
```

Семь языков × стейкинг/профиль/арена/повтор/параметры/KPI × 360/768/1280 px.
Локаль браузера принудительно `en-US`, часовой пояс Europe/Prague: формат чисел и даты
должен определяться выбранным языком приложения, а не настройками браузера.
Тест проверяет текстовые глифы и ширину страницы, сохраняет строку ввода суммы,
восстанавливает старое `signing` и открывает KPI через переподключение кошелька.
API/кошелёк — mock, внешние HTTP/RPC/WS заблокированы, подписи транзакций запрещены.
Нули, отсутствующие суммы и неизменность данных дополнительно проверены в реальных
компонентах в `client/src/app/smoke.test.tsx`.

Холодная загрузка заголовка ожидается до 30 секунд без автоматического повтора теста.
В этой среде полный последовательный mock-прогон занял 33,6 минуты: оболочке нужен
соответствующий лимит либо запускайте файлы отдельно. Финальный результат этапа:
44 mock-теста + 14 отдельных error-тестов; 15 пропусков обычного прогона намеренные.

## Локализация: модальные окна

```bash
npm run e2e:build
npm run e2e:types
npx playwright test tests/e2e/modal-localization.spec.ts --project=desktop-chromium --workers=1
```

Семь языков, 360/1280 px: доступность хендла и переведённая услуга, доступные имена полей,
сумма снятия/«всё», пример цены в локальном формате, продажа из вложенной карточки,
Tab/Escape и возврат фокуса/прокрутки. Подтверждение оплаты/транзакции не нажимается.
Карточка открывается с клавиатуры; её анимация действительно выключена при уменьшении
движения, а не обходится `force`-кликом. Кошелёк запрещает подписи, внешняя сеть заблокирована.

На восьмом этапе 7 новых сценариев + 21 проверка live-localization/mock-shell + 14 отдельных
error-сценариев прошли. Это целевой регрессионный прогон, не новый полный прогон всего e2e.
