# Fix pass 2026-09-29 · красный `backend` (TS6142) и ложные срабатывания сканера ключей

Две точечные правки: джоба `backend` падала на типчеке `tests/localnet` из-за не заданного
`--jsx`, а джоба `security` принимала файлы индонезийских переводов `id.json` за ключи.

## 1. `backend` · TS6142 в `client/src/api/mock/rights.ts`

`npx tsc -p tests/localnet --noEmit` падал:

```
client/src/api/mock/rights.ts(4,27): error TS6142: Module '@/features/rights/Rights'
was resolved to 'client/src/features/rights/Rights.tsx', but '--jsx' is not set.
```

Цепочка: спеки localnet импортируют клиентские билдеры → `api/mock/rights.ts` делает
`import type { Case } from '@/features/rights/Rights'` → файл — `.tsx`. `tests/localnet/tsconfig.json`
обещает в комментарии «Mirrors client/tsconfig.json», но зеркало было неполным: флага `jsx` в нём
не было, и tsc отказывался подтягивать `.tsx` в компиляцию. Ошибка при этом указывала на
`rights.ts` — файл-импортёр, а не на настоящий виновник.

| Файл | Правка |
|---|---|
| `tests/localnet/tsconfig.json` | добавлен `"jsx": "react-jsx"` с комментарием, почему зеркало обязано его нести |

## 2. `security` · `id.json` переводов против `id.json` ключей

Шаг «no committed keypairs outside tests/localnet/fixtures» был однострочником:

```bash
git ls-files | grep -E '(-keypair|keypair|id)\.json$' | grep -v '^tests/localnet/fixtures/'
```

Альтернатива `id` задумывалась против дефолтного вывода `solana-keygen` (`id.json`), но матчила
любой путь, кончающийся на `id.json`. `id` — это код индонезийского в ISO 639-1, поэтому каждый
merge джоба security сжигала на пяти файлах переводов:

```
client/src/shared/i18n/diagnostics/id.json
client/src/shared/i18n/failures/id.json
client/src/shared/i18n/rights/id.json
client/src/shared/lib/legal-copy/id.json
scripts/landing/locales/id.json
```

Плюс суффикс ловил любое «…id.json» (`valid.json`, `grid-id.json`). Гейт переехал в
`scripts/committed-keypairs.ts` по общему правилу репозитория (скрипт + `--selftest` + тест):
имя решает только там, где оно однозначно, неоднозначное — решает содержимое.

| Случай | Решение |
|---|---|
| `*keypair*.json` вне `tests/localnet/fixtures/` | флаг по имени — перевод так не называется |
| путь кончается на `id.json` | флаг только если тело — JSON-массив из ровно 64 uint8 (форма вывода `solana-keygen`); объект строк — перевод |
| `tests/localnet/fixtures/` | разрешено целиком (там живёт мок-keypair оракула, как и раньше) |
| `id.json`, который не удалось прочитать | fail-closed — флаг |

| Файл | Что внутри |
|---|---|
| `scripts/committed-keypairs.ts` | предикаты `isKeypairContent`/`scan` + `--selftest` (14 синтетических кейсов: утечка под локальным путём, 63 байта, значения > 255, не-JSON, fixtures, fail-closed) |
| `package.json` | скрипт `keypairs:scan` |
| `.github/workflows/ci.yml` | шаг заменён на `npm run keypairs:scan -- --selftest && npm run keypairs:scan` (имя шага сохранено) |
| `tests/security/committed-keypairs.test.ts` | регресс: пять реально трекаемых локалей не флагаются (плюс динамический обход всех трекаемых `*id.json`), 64 uint8 флагаются где бы ни прятались, `*keypair*.json` флагается по имени, fixtures разрешены |

Проверено end-to-end на одноразовом git-репозитории: закоммиченный `id.json` с 64 байтами даёт
exit 1 со списком, локаль `i18n/id.json` рядом — молча пропускается, `target/deploy/x-keypair.json` —
флаг по имени.
